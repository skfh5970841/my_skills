### reference.md (style)
- P-RHYTHM-C "역접 단독 배치('그런데.')" 예시: 그런데 단독 사용은 원전에서 드묾. 역접 주력은 하지만/다만. ⚠️
- 전환어 테이블의 빈도 라벨(그런데=높음): ❌ 실측과 불일치 → 재작성

### template.md (style)
- 질문형 도입을 첫 번째 대표 유형으로 제시: ⚠️ 위 3번과 동일 사유로 재배열
- 예시 3종(세금/자유/마르크스)이 reference·SKILL과 중복 — 딥리서치 2 권고대로 **예시 다양화** 필요 (예시 소재 복사 방지)

### transformation_rules.md (style)
- 구조는 건전하나 advisor 버전(RULE-XX+조건 판단+수정 후 예시)이 더 발전함 → 통합 필요

### anti_patterns.md (style)
- "아류작 4패턴" 등 프레임은 유효. advisor 버전의 **수정 후(before/after) 예시**가 TICL 근거(contrastive explanation)와 부합 → 통합 시 채택

### 실측 검증 포인트
- advisor의 P-STRUCTURE-C(A/B 인물화) = 로컬 실측의 인용 장치 12.7%와 정확히 대응. **경험적으로 타당한 추가**였으므로 style에도 반영해야 함.
- advisor mode_write.md 2.4의 전환어 예시("그런데","사실","결국","다시 말하면")도 실측 반박 대상 포함 — 모드 파일에도 동일 오류 전파됨.

### 경계 재설계안 (Phase E에서 최종안 제시)
- **Single source of truth**: 문체 레퍼런스 4종은 한 곳(예: `chaesajang-style/`)에만 두고 advisor는 조건부 로딩 경로로 참조. 또는 공유 디렉토리(`_shared/chaesajang/`) 신설.
- 역할 선긋기: style = "문장 생산·변환 엔진"(무모드), advisor = "사고·구조 워크플로우"(CONSULT/OUTLINE/WRITE 모드 관리) — 현재 description도 이렇게 갈림. 유지하되 파일은 공유.
- agentskills spec 준수: SKILL.md <500 lines/5k tokens(현재 둘 다 충족), 파일 로딩 조건 명시(현재 style은 "참고" 수준 → 조건부 트리거로 강화).

## 4. Phase D로 넘기는 검증 과제

4. 패턴 과적(반복→수렴 남발 등)이 관측되는가
