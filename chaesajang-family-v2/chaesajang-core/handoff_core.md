# handoff_core.md — 계열 공통 핸드오프 패킷

채사장 계열 스킬 사이를 이동할 때 맥락이 유실되지 않도록 하는 표준이다.
대화에서 발견한 구조가 글쓰기로, 자문에서 잡은 방향이 대본으로 그대로 흐르게 한다.
패킷이 있으면 다음 스킬은 같은 질문을 다시 하지 않는다.

---

## 패킷 구성

**필수 3요소** — 이것이 확보되지 않았으면 전환하지 않거나, 전환 후 짧게 한 번만 확인한다.

- **핵심 질문**: 이 작업이 풀려는 질문. 표면 질문이 아니라 실제 질문.
- **중심 대비**: 긴장 구조를 만드는 두 개념. 분야 횡단의 축이 여기서 나온다.
- **독자 상정**: 누구를 위한 것인가. 글이면 독자, 대본이면 시청자.

**선택 2요소** — 있으면 함께 넘긴다. 없어도 패킷은 성립한다.

- **수렴 문장**: 대화나 자문에서 도달한 한 문장. 도착지의 후보가 된다.
- **살릴 표현**: 원문이나 대화에서 그대로 가져갈 가치가 있는 문장·비유.

---

## 발신 규칙

다른 스킬(또는 모드)로의 전환을 제안하는 시점에 패킷을 명시적으로 출력하고,
사용자의 확인을 받은 뒤 전환한다. 패킷 출력은 메타 설명 금지의 예외다 —
전환 순간은 환각 바깥의 순간이므로, 여기서는 도구여도 된다.

출력 형식 (산문 한 단락이어도, 항목이어도 좋다):

```
지금까지 잡힌 것 —
핵심 질문: 우리는 왜 쉬어도 쉬는 것 같지 않은가
중심 대비: 회복(몸의 문제) vs 귀환(자리의 문제)
독자: 퇴근 후에도 일이 머리에서 안 빠지는 직장인
수렴 문장: 휴식은 멈추는 기술이 아니라 돌아오는 기술이다

이대로 글쓰기로 넘어갈까?
```

---

## 수신 규칙

스킬 진입 시 대화 맥락에 패킷(또는 그에 준하는 합의)이 있는지 먼저 본다.

- **있다** → 재질문 없이 사용한다. 필수 3요소를 다시 묻는 것은 핸드오프 실패다.
- **일부만 있다** → 빠진 필수 요소만 짧게 한 번 확인한다.
- **없다** → 각 스킬의 기본 진입 절차를 따른다.

패킷의 내용과 사용자의 직전 발언이 충돌하면 직전 발언이 우선한다.
패킷은 계약이 아니라 출발점이다.

---

## 스킬별 발신 · 수신

| 스킬 | 발신 시점 | 수신 시 동작 |
|---|---|---|
| dialogue | 사용자가 글·대본화를 원해 전환을 안내할 때 | (수신 없음 — 대화는 백지에서 시작해도 된다) |
| advisor | CONSULT→OUTLINE→WRITE 모드 전환마다, 또는 style/scripter로 보낼 때 | 패킷을 Step 2.5의 확보 항목으로 그대로 사용 |
| style | (발신 없음 — 최종 산출 스킬) | 창작 모드의 구조 골격, 변환 모드의 진단 기준으로 사용 |
| scripter | (발신 없음 — 최종 산출 스킬) | 자료 진단의 중심 질문·시청자 가설로 사용. 사용자 질문을 5개에서 1~2개로 줄인다 |

dialogue의 발신은 대화의 끝이 아니다. 패킷을 출력한 뒤에도
사용자가 전환을 원하지 않으면 대화는 계속된다.
